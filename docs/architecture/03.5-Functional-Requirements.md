# 1. Pendahuluan

## 1.1 Tujuan

Dokumen ini mendefinisikan kebutuhan fungsional (Functional Requirements) dan kebutuhan non-fungsional (Non-Functional Requirements) untuk modul Digital Document Management System (DDMS).

Dokumen ini menjadi dasar penyusunan:

- ERD
- Business Process
- Service Layer
- Backend Design
- Frontend Design

---

# 2. Ruang Lingkup

DDMS bertanggung jawab untuk:

- Pembuatan dokumen
- Approval dokumen
- Penomoran dokumen
- QR Verification
- Repository Dokumen
- Riwayat Pengiriman
- Riwayat Verifikasi

DDMS tidak mengambil alih workflow bisnis dari Proposal, Event, Contract, Invoice, maupun Payment.

---

# 3. Aktor

| Aktor | Deskripsi |
|--------|-----------|
| Super Administrator | Mengelola konfigurasi DDMS. |
| Admin | Membuat dan mengelola dokumen. |
| Director | Melakukan approval dokumen resmi. |
| Client | Melihat dan mengunduh dokumen miliknya. |
| Public | Melakukan verifikasi QR. |

---

# 5. Non Functional Requirements

| ID | Requirement |
|----|-------------|
| NFR-001 | Generate PDF maksimal 5 detik. |
| NFR-002 | Repository mendukung pencarian cepat. |
| NFR-003 | Approval menggunakan PIN yang terenkripsi. |
| NFR-004 | Audit Trail tidak dapat diubah. |
| NFR-005 | QR Verification tersedia secara publik. |
| NFR-006 | Semua aktivitas dicatat pada audit log. |
| NFR-007 | Repository mendukung penyimpanan jangka panjang. |

---

# 6. Assumption

- Sistem menggunakan autentikasi Laravel.
- Seluruh dokumen berbentuk PDF.
- QR Code mengarah ke halaman verifikasi publik.
- Approval dilakukan oleh Director.

---

# 7. Constraint

- DDMS tidak mengubah workflow Proposal.
- DDMS tidak mengubah workflow Payment.
- DDMS tidak mengubah workflow Event.
- Repository hanya menyimpan hasil akhir dokumen.
